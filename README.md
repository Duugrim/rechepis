# Речепись

Локальная утилита для **тематических голосовых записей**: говорите, пока нужно, — программа сама режет речь на куски по паузам, чистит звук и расшифровывает его моделью [GigaAM v3](https://github.com/salute-developers/GigaAM) **прямо на вашем компьютере**. Голос никуда не отправляется.

Ориентир: редкие, но длинные наговоры по заранее известной теме — не «быстрая диктовка в курсор».

> **English in short.** Rechepis ("Речепись") is a local web app (Python + FastAPI) for long, topic-based voice notes in Russian.
> It records from the browser microphone, cuts speech into short segments at pauses, denoises and levels each segment, and transcribes it
> offline with the open GigaAM v3 model. Nothing leaves your machine. Windows is the tested platform. See [Установка](#установка); the license is MIT.

## Возможности

- запись с микрофона в браузере; звук сессии хранится целиком и **никогда не меняется**;
- автоматическая нарезка на сегменты по паузам, с предпросмотром на волне и возможностью «пересобрать» сессию с другими настройками;
- очистка (срез низких частот, подавление ровного шума) и выравнивание громкости — над копией каждого сегмента;
- локальная расшифровка GigaAM v3 с пунктуацией; расшифровка идёт, пока вы говорите дальше;
- прослушивание сегмента (оригинал и после обработки), повторная расшифровка с другой обработкой, подробные сообщения об ошибках.

## Три уровня

| Что | Откуда берётся |
|---|---|
| **Запись** | тема («Идеи по релизу»); создаётся кнопкой «+» в библиотеке |
| **Сессия** | одно нажатие «Начать сессию» → «Завершить» внутри записи. Звук сессии хранится целиком, как записан |
| **Сегмент** | кусок речи (обычно 5–20 с), на которые сессия **автоматически** режется по паузам. Сегмент — единица распознавания |

## Установка

Проверялось на Windows 11. Серверная часть — обычный Python, но лаунчеры — `.bat`, а кнопки «Папка» используют `os.startfile`; на другой системе это придётся доработать.

### Готовая сборка (для обычных пользователей)

Скачайте со страницы Releases архив `Rechepis-<версия>-win64.zip` (≈ 250 МБ), распакуйте его и запустите **`Start Rechepis.bat`**. Python и все библиотеки уже внутри, ничего ставить не нужно. При первом запуске программа сама предложит скачать модель (≈ 430 МБ, один раз). Подробности для пользователя — в `README.txt` внутри архива. Записи и настройки лежат в папке `data\` рядом с программой.

### Из исходников (для разработки)

Нужен Python 3.12+ (проверено на 3.14). Скачайте репозиторий (`git clone` или ZIP со страницы GitHub) и в его папке выполните:

```powershell
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
```

Модель GigaAM ставится отдельно (PyTorch и пр., около 1 ГБ):

```powershell
.\Install GigaAM.bat
```

Модель программа предложит скачать при первом запуске (≈ 430 МБ, один раз, лежит в `models\`); то же можно сделать в **Настройки → Распознавание → GigaAM → Скачать**.
Пока модель не скачана, можно выбрать «Не отправлять»: звук запишется и нарежется, а расшифровать его можно позже.

## Запуск

**`Start Rechepis.bat`**. Страница открывается в браузере сама, как только сервер ответит (первый запуск занимает несколько секунд). Закрытие окна останавливает сервер. Интерфейс: [http://127.0.0.1:8765](http://127.0.0.1:8765)
(микрофон в браузере работает только на `127.0.0.1` / `localhost`).

Если порт 8765 занят, скрипт сообщит, каким процессом, и ничего не будет закрывать сам. Чтобы запустить на другом порту, задайте `RECHEPIS_PORT` перед запуском (`set RECHEPIS_PORT=8800`). `RECHEPIS_NO_BROWSER=1` отключает автоматическое открытие страницы.

Скрипт один для разработки и для релиза: если рядом есть папка `python\` (так устроен архив), он запускает её Python и хранит данные в `data\`; иначе берёт `.venv`, а данные лежат в корне проекта.

## Как работать

1. Создайте запись, укажите тему.
2. На панели записи выберите, **отправлять ли сегменты на расшифровку**: `GigaAM` или `Не отправлять` (тогда сегменты только запишутся). Выбор запоминается; для каждой сессии его можно поменять.
3. **Начать сессию** → говорите → **Завершить сессию**. Пока вы говорите, сегменты появляются в списке и сразу уходят на расшифровку.
4. Любой сегмент можно прослушать (оригинал и после обработки), отправить заново с другой обработкой звука и сравнить результаты.
5. Сессию можно **пересобрать**: нарезать заново с другими настройками (с предпросмотром разрезов на волне).

Статус сегмента в списке: кнопка `Г` — пунктир «не отправлялся» (клик — отправить), вращающийся индикатор «в работе», `✓` «готово» (клик — открыть результат), `✗` «ошибка» (клик — повторить). Тексты записи собираются из сегментов: пауза между сегментами короче 1,5 с (настраивается) — один абзац, длиннее — пустая строка.

## Автоматическая обработка

Всё работает на сервере, над звуком в 16 кГц. **Оригинал записи не меняется никогда**: обрабатывается копия каждого сегмента, и заново — если вы отправляете его ещё раз с другими настройками.

### 1. Нарезка

Детектор речи следит за громкостью кадров по 20 мс. Шум комнаты оценивается автоматически (низкий перцентиль последних секунд, «цифровой нуль» не считается), поэтому шумная комната просто сдвигает порог.

Правила (по убыванию важности):

1. тишина длиннее **долгой паузы** (1,4 с) всегда завершает сегмент; такой же долгий *провал* (см. ниже) — тоже, если сегмент уже не короче минимума;
2. когда сегмент набрал **желаемую длину** (12 с), его закрывает первая пауза ≥ 0,45 с;
3. на **максимуме** (24 с) сегмент делится по самой длинной паузе внутри, а если речь шла без пауз — в самом тихом месте последних 40 % окна.

Сегмент = речь + **запас** 250 мс по краям. Тишина между сегментами выбрасывается: распознаватели склонны «придумывать» текст на молчании.

«Пауза» — это не только тишина: микрофон, дыхание, комната и автоподстройка усиления браузера почти никогда не дают нулевой уровень между фразами. Поэтому разрез ищется по **провалу** — участку, на `глубину паузы` (20 дБ) тише обычной речи. Эти два порога (чувствительность и глубина паузы) — главные ручки, если на вашем микрофоне что-то режется не так.

Нарезка одинаково работает вживую (сегмент уходит на расшифровку через долю секунды после паузы) и офлайн («Пересобрать…»).

### 2. Очистка

- срез низких частот 80 Гц (гул, стук по столу);
- подавление ровного шума: профиль шума берётся по самым тихим кадрам последних 90 секунд сессии (а не по одному сегменту, где «чистой» тишины почти нет), затем фильтр Винера с оценкой «decision-directed». Убирает вентилятор, шипение, гул сети; чужие голоса и стук клавиш — нет;
- глубже, чем на заданное число дБ, ничего не режется — звук не «проваливается» в цифровую тишину.

### 3. Усиление

Громкость речи в каждом сегменте приводится к −20 дБFS (RMS), усиление ограничено +30 дБ (тихие записи не раздуваются вместе с шумом), пики мягко ограничиваются. Для каждого сегмента считаются уровень речи, шума, запас над шумом, пик и перегруз; тихие, перегруженные и шумные сегменты помечаются.

### Честно о пользе

Современные модели и сами неплохо переносят шум. На записи, которая уже прошла через браузерное шумоподавление (запас над шумом ≈ 20 дБ), разные пресеты обработки отличались в 1–2 % слов. Контрольный опыт с искусственным шумом: при шипении с запасом 3 дБ расхождение с расшифровкой чистого звука падает с 13 % до 11 % слов, при 10 дБ и при гуле — в пределах погрешности. Поэтому главный выигрыш даёт **нарезка** (короткие сегменты распознаются лучше) и **отключение браузерной обработки** на входе (см. ниже), а очистка — страховка для плохих условий. Проверить на своём микрофоне просто: отправьте один сегмент с «Без обработки» и с «Сильная очистка» и сравните тексты в карточке сегмента (справа).

### Захват звука

Браузер отдаёт звук как есть: его шумоподавление, эхоподавление и автоусиление по умолчанию выключены (настраивается на вкладке «Микрофон»), а в 16 кГц звук переводится на сервере полифазным фильтром. Запись идёт через AudioWorklet в отдельном потоке и не прерывается, даже если страница занята.

## Модель

GigaAM v3 работает на этом компьютере (CPU; CUDA, если есть), без интернета. На Ryzen 7 5800X (CPU) это порядка 20× быстрее реального времени, модель загружается ≈ 4 с. Принимает до 25 с за раз — длиннее режется внутри по паузам, поэтому нарезка на сегменты ей особенно подходит.

Варианты: `v3_e2e_rnnt` (по умолчанию: пунктуация, числа цифрами), `v3_e2e_ctc` (быстрее), `v3_rnnt` / `v3_ctc` (без пунктуации, формально меньше ошибок в словах). Выбор и скачивание — в настройках. GigaAM сохраняет «а-а», «я-я», повторы.

### Ошибки

Если сегмент не распознался, в его карточке видно: на какой стадии (подготовка звука / загрузка модели / распознавание), тип исключения, ответ сервиса целиком (если он был), число попыток, контекст (длина, модель, обработка), трассировка и подсказка, что делать. Кнопка «Копировать подробности». Повторить можно с той же или другой обработкой.

## Приватность

- Звук и тексты хранятся только в папке программы (`recordings\`) и никуда не отправляются.
- Сеть используется трижды: `pip` при установке; скачивание модели с серверов Сбера по кнопке «Скачать»; интерфейс подгружает три шрифта с Google Fonts (без сети подставятся системные).
- Сервер слушает только `127.0.0.1`.

## Файлы на диске

```
recordings\
  2026-10-14_185550_rebalans\
    meta.json
    transcript.txt                    # весь текст записи (его вы копируете)
    sessions\
      001\
        meta.json                     # время, настройки нарезки и обработки этой сессии
        audio.wav                     # оригинал, 16 кГц моно (во время записи — audio.pcm)
        transcript.txt
        _archive\segments-…\          # прежние сегменты после «Пересобрать»
        segments\
          001\
            meta.json                 # положение в сессии, уровни, тексты и ошибки
            audio.wav                 # что реально ушло на расшифровку (после обработки)
            gigaam.json               # полный ответ модели
            transcript.txt
models\gigaam\                        # скачанные модели
config.json                           # настройки
```

Файлы пишутся атомарно (временный файл + замена), так что сбой не оставит «половину» метаданных. Если программа закрылась во время записи, при следующем запуске звук сессии восстанавливается, а незавершённые расшифровки помечаются ошибкой «прервано» с кнопкой «Повторить».

## config.json

```json
{
  "language": "ru",
  "gigaam": { "model": "v3_e2e_rnnt", "device": "auto", "threads": 0 },
  "targets": ["gigaam"],              // куда отправлять новые сегменты ([] — только записывать)
  "paragraph_gap_s": 1.5,
  "slicing": { … }, "processing": { … }, "mic": { … }
}
```

Всё это редактируется в «Настройках». Переменная окружения `RECHEPIS_DATA` переносит записи, модели и конфиг в другую папку (так работают тесты; в релизе лаунчер задаёт `data\` рядом с программой). Неизвестные ключи при сохранении отбрасываются.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET / PUT | `/api/config` | настройки, пресеты, состояние модели |
| POST | `/api/providers/gigaam/download` · `/warm` | скачать / загрузить модель |
| GET / POST | `/api/recordings` | список / создать запись |
| GET / PATCH | `/api/recordings/{id}` | запись со всеми сессиями и сегментами / переименовать |
| GET | `…/sessions/{sid}/peaks` · `/audio` | волна и оригинал сессии |
| POST | `…/sessions/{sid}/resegment` | пересобрать (`dry_run` — только предпросмотр) |
| POST | `…/sessions/{sid}/transcribe` | отправить сегменты сессии (`only`: all / missing / errors) |
| GET | `…/segments/{gid}/audio?kind=raw\|processed` | прослушать сегмент |
| POST / PATCH | `…/segments/{gid}/transcribe` · `…/segments/{gid}` | отправить сегмент / закрепить выбранный текст |
| WS | `/ws/capture` | захват сессии (PCM 16 бит моно) |
| WS | `/ws/events` | события: новые сегменты, готовые тексты, прогресс загрузки модели |

## Сборка релиза

Переносимый архив собирается одной командой на Windows (подойдёт любой Python 3.10+ с pip, например из `.venv`):

```powershell
.\.venv\Scripts\python.exe release\build_release.py
```

Скрипт скачивает встраиваемый Python (версия и SHA-256 зашиты в нём), ставит пакеты ровно тех версий, что в `requirements-release.txt`, и GigaAM с закреплённого коммита, кладёт рядом приложение, лаунчер и `README.txt`, собирает `THIRD-PARTY-LICENSES.txt`, прогоняет импорт всех модулей встроенным Python и пишет `dist\Rechepis-<версия>-win64.zip` с контрольной суммой. Готовая папка остаётся в `build\work\`, загрузки — в `build\cache\` (повторная сборка их не скачивает). Версия берётся из `app/__init__.py`. Сборка занимает около трёх минут; ключ `--no-precompile` убирает предкомпилированный байт-код: архив меньше (≈ 190 МБ вместо ≈ 250 МБ), но первый запуск медленнее.

Что стоит знать:

- Версии в `requirements-release.txt` зафиксированы по среде разработки; после обновления зависимостей обновите файл и прогоните тесты до сборки.
- Ни встраиваемый Python, ни PyTorch не содержат `msvcp140.dll`, а на чистой Windows его может не быть. Скрипт находит по таблицам импорта нужные DLL среды выполнения Visual C++ и копирует их из `System32` машины сборки рядом с `python.exe`.
- Сборка рассчитана на процессор: PyTorch с PyPI для Windows без CUDA.
- Архив не подписан, поэтому Windows покажет предупреждение SmartScreen (в `README.txt` для пользователя это объяснено).
- Два пакета (`antlr4-python3-runtime`, `sentencepiece`) не содержат файла лицензии; их тексты, взятые из репозиториев проектов, лежат в `release\licenses\` и попадают в `THIRD-PARTY-LICENSES.txt`. При смене версий этих пакетов сверьте тексты.

## Ограничения

- Детектор — энергетический, а не нейросетевой: рассчитан на один голос у микрофона. Музыка, телевизор или второй говорящий рядом считаются речью.
- Подавляется только ровный шум; вентилятор — да, чужие голоса — нет.
- GigaAM — модель для русского языка.
